UI direction and build order

Reuse the Flutter theme and components already built. Approve hierarchy and behavior here first; final illustration and visual polish come after the connected flow works.

01 / foundations

Calm, clear, spacious

Light surfaces, forest-green actions, cream backgrounds and mint selection. One strong primary action per screen.

  • Titles 26–28; body 16; supporting text 14.
  • Spacing 4, 8, 12, 16, 24, 32.
  • Cards 16-radius; controls 12-radius.
  • 48px minimum touch targets, safe areas and scalable text.

02 / reuse

Components, not one-off screens

Use AppButton, AppTextField, AppCard, AvatarBadge and shared loading/empty/error views.

  • One community-card pattern.
  • One room-card pattern with occupancy text.
  • One goal sheet and confirmation pattern.
  • One scene fed by seat states and callbacks.

03 / room

The visual center of the app

Six fixed seats in one reusable 2D room. Background, avatars and decorations are separate layers.

  • Never bake people or text into artwork.
  • Align taps and art with shared coordinates.
  • Show labels as well as colors.
  • Render live state; never infer a server reservation from a tap.

First: confirm the structure

Review the four tabs, Discover hierarchy, room actions, invitation consent and focused-session navigation. Confirm owners and repository inputs.

Output: agreed screen/state inventory.

Next: detailed key screens

Refine Discover, SIG/subgroup, room lobby and focus/summary. Then apply their components to auth, history and scanner states.

Output: implementation-ready references.

Then: connect and rehearse

Implement with fixtures, connect shared services, test on both phones and rehearse the 60-second demo cycle. Defer optional rewards/charts.

Output: a reliable five-minute demonstration.
